# ReadArticles 项目代码审查

## 规范入口与授权

先阅读仓库根目录 `AGENTS.md`、`docs/project-contract.md`，以及 WindowsAppPlaybook 的 `docs/skills/windows-app-review/SKILL.md` 和其引用的通用规范。本 Skill 仅补充 ReadArticles 特有规则，避免在两个仓库重复定义通用规范。

优先级：用户本轮明确要求 → 已确认的项目行为及数据格式 → 项目契约 → WindowsAppPlaybook 默认规范 → 一般建议。共用规范不可用时，以项目契约与源码为依据并报告缺失。只读审查不等于授权修改、删除、提交、推送或合并；具体 Git 操作遵循本轮明确授权。

## 审查步骤

1. 固定被审查的分支、commit、授权范围和可见的工作区状态；不能访问本地工作区时不得声称检查过本地改动。
2. 从主要入口追踪状态、业务、存储与输出：书库发现与逐层展开、文章打开、词汇编辑和恢复、音频播放、窗口生命周期、设置保存及发布。专项审查沿受影响路径检查调用方和失败路径。
3. 逐项记录文件/方法、触发条件、可观察影响、证据、修复方向及回归方法；分为**正确性必修**、**可靠性/维护性建议**、**可选风格**、**待验证**，不将个人风格偏好误报为缺陷。
4. 按第一性原理与最小必要设计逐项检查：先质疑必要性，再删除不必要的旧规则、状态或分支，随后合并或直接修改现有实现；最后才增加必要实体。**禁止**为追求代码行数更少而损害已确认的功能契约、数据安全、可恢复性和可维护性。本轮 Passage 格式明确为破坏性升级，不得以旧格式兼容为理由保留 SID、句子音频或引入迁移层。
5. 使用项目契约里的真实测试和发布入口；区分静态检查、自动化测试、Windows UI/音频实机、发布目录验证，逐项报告通过、失败、跳过和未执行。
6. 仅在授权整改后修改代码；仅在明确授权时执行 Git 提交、推送和合并。commit message 使用英文，准确描述实际变更。

## ReadArticles 专属审查不变量

- **导航与线程：** 根目录只发现直接包含 `book.json` 的书籍；子树每次只加载一级，后台枚举不能阻塞 WPF Dispatcher。折叠、切库和退出时要让旧请求失效。目录名恰为 `cache` 时全局隐藏；父目录直接存在任意 `.json` 文件时，名称包含 `audio` 的直接子目录隐藏；均忽略大小写。过滤只作用于导航，不阻止真实文件访问。
- **文章与词汇：** 正文 JSON 与媒体只读。应用只写当前配套词汇 JSON，以及契约约定的 userdata 设置和日志。保留已确认的 Passage 三字段格式（JSON `title` 唯一决定正文标题，`paragraphs` 是二维句子字符串数组）、句子边界及占位符校验、词汇扩展字段、外部修改检测、保存互斥、临时文件提交、备份与救援副本。加载失败不能破坏原本已提交的阅读状态。
- **音频：** 不提供句子级音频。词汇音频在 `audio/`，根据 ASCII stem 和 uk/us 后缀推导，MP3 存在时优先且解码失败不回退 WAV。全文音频仅搜索 Passage 同级目录，先按 M4A/MP3/WAV 格式优先级、再按文件名升序建立唯一候选序列；打开失败继续列表下一个（包括同格式文件），成功打开即停止搜索，全部失败才提示。用户停止、切文章及退出须取消尚未完成的候选遍历；成功打开后的播放故障不切换至另一录音。文章与发音使用独立通道，过期回调不能改变新播放状态。
- **UI 与状态：** 检查当前文章、词表、树选择和通知状态一致性。失败切换应保留旧文章及词表。Toast 的错误消息不能自动消失，旧状态只有在证实无使用者后才删除。View/code-behind 可保留必要的 WPF 控件行为，不机械要求清空。
- **路径与发布：** 保护路径越界、reparse points、用户数据及恢复副本。当前项目契约为 .NET 10、Windows x64、framework-dependent 单文件便携目录，设置位于 EXE 同级 `userdata/`。既有 `tools/Publish.ps1` 受发布验证保护；通用规范的默认新发布入口不自动覆盖已确认的项目选择。不得因清理而删除唯一有效数据或备份。

## 验证入口与报告

从仓库根目录在 Windows PowerShell 运行：

- 构建：`dotnet build ReadArticles -c Release`
- 核心测试：`.\tools\Test.ps1 -Suite Core`
- UI：`.\tools\Test.ps1 -Suite UI`
- 全量：`.\tools\Test.ps1 -Suite Full`
- 发布及实际 EXE：`.\tools\Publish.ps1`、`.\tools\Test-PublishedApp.ps1`

真实文章库和用户数据仅按约定使用隔离副本进行破坏性测试。报告包括代码版本、覆盖范围、发现、证据、整改建议、真实执行的命令及结果、未完成验证、Git 变更与风险。
